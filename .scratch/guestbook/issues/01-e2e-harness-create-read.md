# 01: E2E 테스트 기반 구축 + 작성·조회 시나리오

**What to build:** 개발자가 명령 하나로 실제 브라우저에서 방명록 페이지를 조작하는 E2E 테스트를 돌릴 수 있게 한다. 이 명령은 테스트 전용 Neon 브랜치에 스키마를 적용하고, 앱을 띄운 뒤, 테스트를 실행한다. 첫 테스트로 방명록 글 작성과 조회 흐름을 검증한다. 테스트 경계는 스펙에 정한 대로 "브라우저로 방명록 페이지를 조작하는 것" 하나뿐이며, 화면에서 관찰할 수 있는 동작만 확인한다. 나머지 티켓(02–04)은 모두 이 기반 위에서 작성한다.

참고: docs/specs/0001-guestbook.md (Testing Decisions, User Stories 1–26)

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 테스트용 `DATABASE_URL`(운영 DB와 다른 Neon 브랜치)을 받아, 스키마 적용 → 앱 실행 → Playwright 실행을 명령 하나로 수행한다.
- [x] 테스트용 `DATABASE_URL`이 없거나 운영 DB 주소와 같으면 테스트를 시작하지 않고 실패한다. 단, 실행 단위로 명시적으로 허용(`E2E_ALLOW_PRODUCTION_DB=1`)한 경우에만 운영 DB로 실행할 수 있다(2026-09-30 사용자 결정: 테스트 브랜치 준비 전 1회 허용).
- [x] 각 테스트는 고유한 이름 태그를 붙인 자기 방명록 글만 찾아 검증하고, 끝나면 UI로 직접 삭제해 정리한다. 테스트끼리 서로 간섭하지 않는다.
- [x] 작성: 이름·메시지·글 비밀번호를 입력해 남기면 목록에 나타나고, 폼이 비워진다.
- [x] 조회: 새로 남긴 방명록 글이 먼저 남긴 글보다 위에 보인다(최신순).
- [x] 조회: 작성 시각이 `YYYY-MM-DD HH:mm` 형식(KST)으로 보이고, 툴팁에는 초 단위 시각이 있다.
- [x] 조회: 메시지의 줄바꿈이 유지되고, `<b>` 같은 HTML은 해석되지 않고 글자 그대로 보인다.
- [x] 조회: 방명록 글이 하나도 없을 때 첫 글을 남기라는 안내가 보인다. 이 검증은 비어 있는 테스트 DB에서만 수행한다.
- [x] 새로고침 뒤에도 남긴 방명록 글이 그대로 보인다(실제로 저장되었는지 확인).
- [x] 저장소 안내 문서(README 등)에 테스트 실행 방법과 필요한 환경변수를 적는다.
