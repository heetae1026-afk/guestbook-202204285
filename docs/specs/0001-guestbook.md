# 미니 방명록

## Problem Statement

방문자가 회원가입이나 로그인 없이 가볍게 이름과 메시지를 남기고, 다른 사람들이 남긴 글을 볼 수 있는 곳이 필요하다. 동시에, 계정이 없어도 자기가 남긴 방명록 글은 자기만 고치거나 지울 수 있어야 하고, 남이 함부로 내 글을 바꾸거나 없애지 못해야 한다.

## Solution

한 페이지짜리 방명록. 방문자는 이름, 메시지, 글 비밀번호를 입력해 방명록 글을 남긴다. 모든 방명록 글은 작성 시각과 함께 최신순으로 한 화면에 모두 보인다. 글쓴이(그 글의 글 비밀번호를 아는 사람)는 글 비밀번호를 입력해 메시지를 수정하거나 방명록 글을 삭제할 수 있다. 글 비밀번호가 틀리면 요청은 거부되고 그 사실이 해당 방명록 글 자리에 안내된다.

## User Stories

### 작성

1. 방문자로서, 로그인 없이 이름과 메시지를 입력해 방명록 글을 남기고 싶다. 가입 절차 없이 바로 흔적을 남길 수 있도록.
2. 방문자로서, 방명록 글을 남길 때 글 비밀번호를 함께 정하고 싶다. 나중에 내 글을 나만 수정·삭제할 수 있도록.
3. 방문자로서, 이름을 입력하지 않으면 안내를 받고 싶다. 빈 이름의 글이 올라가지 않도록.
4. 방문자로서, 메시지를 입력하지 않으면 안내를 받고 싶다. 빈 글이 올라가지 않도록.
5. 방문자로서, 공백만 입력한 이름이나 메시지는 입력하지 않은 것으로 취급되길 원한다. 의미 없는 글이 쌓이지 않도록.
6. 방문자로서, 이름이 20자를 넘으면 안내를 받고 싶다. 목록이 깨지지 않도록.
7. 방문자로서, 메시지가 500자를 넘으면 안내를 받고 싶다. 방명록이 짧은 글 위주로 유지되도록.
8. 방문자로서, 글 비밀번호가 4자 미만이거나 64자를 넘으면 안내를 받고 싶다. 너무 약하거나 비정상적인 비밀번호를 쓰지 않도록.
9. 방문자로서, 입력이 거부되었을 때 내가 쓴 이름과 메시지가 지워지지 않길 원한다. 다시 처음부터 쓰지 않아도 되도록.
10. 방문자로서, 방명록 글이 남겨지면 입력 폼이 비워지길 원한다. 글이 잘 남겨졌음을 알 수 있도록.
11. 방문자로서, 남기는 중에는 버튼이 비활성화되고 진행 중임이 보이길 원한다. 같은 글을 두 번 올리지 않도록.
12. 방문자로서, 글 비밀번호를 잊으면 수정·삭제할 수 없다는 안내를 미리 보고 싶다. 비밀번호를 신중히 정할 수 있도록.
13. 방문자로서, 쉬운 비밀번호를 피하라는 안내를 보고 싶다. 남이 내 글 비밀번호를 쉽게 추측하지 못하도록.
14. 방문자로서, 다른 사람이 이미 쓴 이름으로도 방명록 글을 남길 수 있길 원한다. 이름은 신원이 아니라 표시용 라벨이므로.

### 조회

15. 방문자로서, 누구나 전체 방명록 글 목록을 볼 수 있길 원한다. 로그인 없이 다른 사람의 글을 읽을 수 있도록.
16. 방문자로서, 가장 최근에 작성된 방명록 글이 맨 위에 보이길 원한다. 새 글을 먼저 볼 수 있도록.
17. 방문자로서, 각 방명록 글의 이름, 메시지, 작성 시각을 함께 보고 싶다. 누가 언제 남겼는지 알 수 있도록.
18. 방문자로서, 작성 시각이 한국 시간(KST) 기준 `YYYY-MM-DD HH:mm` 형식으로 보이길 원한다. 어디서 접속해도 같은 시각을 보도록.
19. 방문자로서, 작성 시각에 마우스를 올리면 초 단위까지의 전체 시각을 보고 싶다. 정확한 시각이 궁금할 때 확인할 수 있도록.
20. 방문자로서, 수정된 방명록 글에는 "(수정됨)" 표시가 보이길 원한다. 처음 쓴 내용과 다를 수 있음을 알 수 있도록.
21. 방문자로서, "(수정됨)"에 마우스를 올리면 마지막 수정 시각을 보고 싶다. 언제 바뀌었는지 알 수 있도록.
22. 방문자로서, 메시지의 줄바꿈이 그대로 보이길 원한다. 글쓴이가 의도한 모양대로 읽을 수 있도록.
23. 방문자로서, 메시지에 HTML이나 스크립트가 들어 있어도 글자 그대로 보이길 원한다. 악성 글에 의해 피해를 입지 않도록.
24. 방문자로서, 방명록 글이 하나도 없을 때 첫 글을 남기라는 안내를 보고 싶다. 빈 화면에 당황하지 않도록.
25. 방문자로서, 목록을 불러오는 동안 불러오는 중이라는 표시를 보고 싶다. 페이지가 멈춘 것이 아님을 알 수 있도록.
26. 방문자로서, 누군가 새 글을 남기거나 수정·삭제한 뒤 페이지를 새로 열면 최신 상태가 보이길 원한다. 오래된 목록을 보지 않도록.

### 수정

27. 글쓴이로서, 내 방명록 글의 [수정]을 눌러 그 자리에서 메시지를 고치고 싶다. 다른 화면으로 이동하지 않고 바로 고칠 수 있도록.
28. 글쓴이로서, 수정 폼에 현재 메시지가 미리 채워져 있길 원한다. 일부만 고칠 수 있도록.
29. 글쓴이로서, 수정한 메시지와 글 비밀번호를 한 번에 제출하고 싶다. 확인 단계를 여러 번 거치지 않도록.
30. 글쓴이로서, 글 비밀번호가 맞으면 메시지가 바뀌고 수정 폼이 닫히길 원한다. 수정이 끝났음을 알 수 있도록.
31. 글쓴이로서, 수정 후에도 작성 시각은 처음 값 그대로 유지되길 원한다. 언제 처음 남겼는지가 보존되도록.
32. 글쓴이로서, 이름은 수정할 수 없음을 이해한다. 수정 대상은 메시지뿐이므로.
33. 방문자로서, 글 비밀번호가 틀리면 수정이 거부되고 "글 비밀번호가 일치하지 않습니다. 수정되지 않았습니다."라는 안내를 해당 글 자리에서 보고 싶다. 왜 수정되지 않았는지 알 수 있도록.
34. 글쓴이로서, 글 비밀번호가 틀렸을 때 내가 고쳐 쓴 메시지가 지워지지 않길 원한다. 비밀번호만 다시 입력하면 되도록.
35. 글쓴이로서, 수정한 메시지가 비어 있거나 500자를 넘으면 안내를 받고 싶다. 작성 때와 같은 규칙이 적용되도록.
36. 글쓴이로서, [취소]를 눌러 수정을 그만두고 원래 화면으로 돌아가고 싶다. 실수로 연 수정 폼을 닫을 수 있도록.
37. 글쓴이로서, 수정 폼을 닫았다가 다시 열면 이전 오류 안내가 남아 있지 않길 원한다. 새로 시도하는 것처럼 보이도록.
38. 방문자로서, 다른 방명록 글의 글 비밀번호로는 이 글을 수정할 수 없길 원한다. 권한이 글 하나 단위로만 주어지도록.
39. 방문자로서, 같은 이름을 쓴다는 이유로 남의 글을 수정할 수 없길 원한다. 이름은 권한과 무관하므로.
40. 글쓴이로서, 수정하려는 사이에 글이 이미 삭제되었다면 "이미 삭제되었거나 없는 글입니다."라는 안내를 받고 싶다. 상황을 이해할 수 있도록.

### 삭제

41. 글쓴이로서, 내 방명록 글의 [삭제]를 누르면 그 자리에 글 비밀번호 입력란과 [삭제 확인] 버튼이 나타나길 원한다. 실수로 바로 지워지지 않도록.
42. 글쓴이로서, 글 비밀번호가 맞으면 방명록 글이 목록에서 즉시 사라지길 원한다. 삭제되었음을 알 수 있도록.
43. 글쓴이로서, 삭제는 흔적 없이 영구히 이루어지길 원한다. "삭제된 글입니다" 같은 자리가 남지 않도록.
44. 방문자로서, 글 비밀번호가 틀리면 삭제가 거부되고 "글 비밀번호가 일치하지 않습니다. 삭제되지 않았습니다."라는 안내를 해당 글 자리에서 보고 싶다. 왜 삭제되지 않았는지 알 수 있도록.
45. 방문자로서, 다른 방명록 글의 글 비밀번호로는 이 글을 삭제할 수 없길 원한다. 권한이 글 하나 단위로만 주어지도록.
46. 글쓴이로서, [취소]를 눌러 삭제를 그만두고 싶다. 마음이 바뀌었을 때 되돌릴 수 있도록.
47. 글쓴이로서, 삭제하려는 사이에 글이 이미 삭제되었다면 "이미 삭제되었거나 없는 글입니다."라는 안내를 받고 싶다. 상황을 이해할 수 있도록.

### 보안과 운영

48. 방문자로서, 내 글 비밀번호가 원문 그대로 저장되지 않길 원한다. 저장소가 유출되어도 비밀번호가 드러나지 않도록.
49. 방문자로서, 글 비밀번호나 그 해시가 화면이나 응답으로 절대 전달되지 않길 원한다. 다른 사람이 알아낼 수 없도록.
50. 방문자로서, 화면을 거치지 않고 서버에 직접 요청해도 같은 입력 규칙과 글 비밀번호 확인이 적용되길 원한다. 브라우저 검증을 우회해도 권한이 뚫리지 않도록.
51. 운영자로서, 스팸이나 부적절한 방명록 글은 저장소에서 직접 삭제할 수 있음을 이해한다. 화면에는 관리자 삭제 경로가 없으므로.
52. 운영자로서, 배포 환경에서도 방명록 글이 사라지지 않고 유지되길 원한다. 서버가 재시작되어도 데이터가 남도록.

## Implementation Decisions

- **저장소**: 방명록 글은 Neon 서버리스 Postgres에 저장한다(ADR-0001). 연결 정보는 `DATABASE_URL` 환경변수로 받는다.
- **스키마**: 테이블 하나에 방명록 글 하나가 한 행이다. 스키마는 저장소에 SQL 파일로 두고 별도 설정 명령으로 한 번 적용한다. 요청을 처리하는 코드에서는 테이블을 만들지 않는다.
  ```
  entries
    id            bigint identity PK
    name          varchar(20)  not null
    message       varchar(500) not null
    password_hash text         not null
    created_at    timestamptz  not null default now()
    updated_at    timestamptz  null        -- null이면 수정된 적 없음
  index (created_at desc, id desc)
  ```
- **글 비밀번호**: Node 내장 scrypt로 방명록 글마다 무작위 salt를 만들어 해시하고, 확인할 때는 timing-safe 방식으로 비교한다. 저장 형식은 `scrypt$<salt>$<hash>`이다(ADR-0002). 해시는 서버 밖으로 나가지 않는다.
- **무차별 대입 방어 없음**: 틀린 비밀번호를 반복 입력해도 제한하거나 잠그지 않는다. 폼에 안내 문구를 두는 것으로 대신한다(ADR-0002).
- **관리자 경로 없음**: 방명록 글의 수정·삭제는 그 글의 글 비밀번호로만 허용한다(ADR-0003).
- **모듈 구성**
  - *데이터 모듈*: DB 클라이언트와 "전체 방명록 글 최신순 조회"를 제공한다. 조회 결과에 비밀번호 해시는 포함하지 않는다.
  - *비밀번호 모듈*: 해시 만들기와 비밀번호 확인, 두 기능만 공개한다.
  - *서버 액션 모듈*: 작성·수정·삭제 세 가지 액션을 제공한다. 셋 다 `(이전 상태, FormData) → ActionState` 형태이고, 입력 검증과 권한 확인은 모두 여기서 한다. 성공하면 페이지를 다시 검증(revalidate)한다.
  - *페이지*: 서버 컴포넌트다. 요청마다 새로 렌더링되도록 `connection()`을 호출하고, 목록 부분은 Suspense로 감싼다. 시각은 서버에서 KST 문자열로 만들어 클라이언트에 전달해, 서버와 브라우저 사이의 hydration 불일치를 막는다.
  - *클라이언트 UI*: 작성 폼과 방명록 글 항목으로 나뉜다. 항목은 보기 / 수정 / 삭제 세 가지 모드를 가진다. 수정 패널과 삭제 패널은 열 때마다 새로 마운트되어 이전 오류 상태를 버린다.
- **액션 결과 계약**
  ```ts
  type ActionState = {
    status: "idle" | "success" | "error";
    error?: string;                               // 사용자에게 그대로 보여 줄 한국어 안내
    fields?: { name?: string; message?: string }; // 오류 시 입력값 되돌려 주기
  };
  ```
- **검증 규칙**: 이름과 메시지는 앞뒤 공백을 제거한 뒤 길이를 잰다. 글 비밀번호는 공백을 제거하지 않는다. 길이는 UTF-16 단위가 아니라 문자(code point) 단위로 세어 Postgres `varchar` 길이와 맞춘다. 제한은 이름 1–20자, 메시지 1–500자, 글 비밀번호 4–64자다. 브라우저 검증은 편의를 위한 것이고, 서버 검증이 기준이다.
- **수정 흐름**: 한 단계로 처리한다. 방명록 글 id, 새 메시지, 글 비밀번호를 한 번에 제출한다. 서버는 검증 → 방명록 글 존재 확인 → 글 비밀번호 확인 → 메시지와 수정 시각 갱신 순서로 처리한다. 성공하면 클라이언트가 액션 안에서 패널을 닫는다. effect는 쓰지 않는다.
- **삭제 흐름**: 글 비밀번호 입력 자체를 확인 단계로 삼는다. 별도의 확인 대화상자는 띄우지 않는다. 성공하면 행을 완전히 삭제한다.
- **안내 문구**: 글 비밀번호가 틀렸을 때와 방명록 글이 없을 때, 그리고 수정과 삭제에 대해 서로 구분되는 문구를 쓴다(User Stories 33, 40, 44, 47).
- **표시**: 메시지는 텍스트로만 렌더링하고 줄바꿈을 유지한다. 작성 시각은 KST 고정 `YYYY-MM-DD HH:mm`이고, 툴팁에 초 단위 시각을 보여 준다.
- **용어**: 코드와 UI 문구는 용어집(방명록 글, 이름, 메시지, 작성 시각, 수정됨, 글 비밀번호, 글쓴이, 삭제)을 따른다.

## Testing Decisions

- **좋은 테스트의 기준**: 사용자가 브라우저에서 관찰할 수 있는 동작만 검증한다. 목록 순서, 보이는 텍스트, 안내 문구, "(수정됨)" 표시, 새로고침 뒤에도 남아 있는지가 대상이다. 해시 형식, SQL, 컴포넌트 내부 상태는 검증하지 않는다.
- **테스트 경계는 하나**: 실행 중인 앱의 방명록 페이지를 Playwright로 조작하는 E2E 테스트다. 저장이 실제로 되었는지는 페이지를 새로고침한 뒤 화면으로 확인한다.
- **필수 시나리오**
  - 작성: 방명록 글이 목록에 나타나고, 성공하면 폼이 비워진다.
  - 조회: 최신순으로 정렬되고, 작성 시각 형식이 맞고, 줄바꿈이 유지되고, HTML이 글자 그대로 보인다.
  - 수정 거부: 틀린 글 비밀번호에 거부 안내가 나오고, 입력한 메시지가 유지되고, 새로고침해도 데이터가 그대로다.
  - 수정 성공: 메시지가 바뀌고, "(수정됨)"이 표시되고, 패널이 닫힌다.
  - 삭제 거부: 다른 방명록 글의 비밀번호로 시도하면 거부 안내가 나오고, 새로고침 뒤에도 글이 남아 있다.
  - 삭제 성공: 새로고침 뒤에 방명록 글이 사라져 있다.
- **데이터 격리**: 테스트는 운영 DB가 아니라 별도의 Neon 브랜치를 가리키는 `DATABASE_URL`로 실행한다. 각 테스트는 고유한 이름 태그로 자기 방명록 글만 찾고, 끝날 때 UI로 직접 삭제해 정리한다.
- **선례**: 저장소에는 아직 테스트가 없다. 구현 과정에서 임시로 돌린 Playwright 스크립트(위 시나리오 14개 검증 항목, 전부 통과)가 선례이며, 이를 저장소의 테스트로 옮긴다.

## Out of Scope

- 회원가입, 로그인, 계정
- 관리자 화면과 관리자 비밀번호. 스팸은 DB에서 직접 삭제한다(ADR-0003).
- 틀린 비밀번호 반복 시도에 대한 레이트리밋이나 잠금(ADR-0002)
- 글 비밀번호의 변경이나 복구
- 이름 수정
- 페이지네이션, "더 보기", 검색
- 삭제된 글의 흔적 남기기(soft delete)
- 마크다운, 링크 자동 변환, 이미지 첨부
- 브라우저에 이름을 저장해 자동으로 채우기
- 상대 시각 표시("3분 전")와 사용자별 시간대

## Further Notes

- 이 스펙은 이미 구현된 기능을 사후에 정리한 것이다. 구현은 위 결정을 따르며, 남은 작업은 E2E 테스트를 저장소로 옮기는 것이다.
- 글 비밀번호가 짧으면(예: 4자리 숫자) 무차별 대입으로 뚫릴 수 있다. 이는 ADR-0002에서 받아들인 위험이다.
